
**Sortable table headers (Fields, Organizers, Addresses, Players, Bookings) — Nov 24, 2026**

All five plain-listing tables in the admin dashboard — Fields, Organizers, Addresses (Welcome package targets), Players, Bookings — now have clickable, sortable column headers. Clicking a header sorts the table by that column; clicking again reverses direction. A chevron icon in each header shows sort state: a neutral up/down icon when unsorted, a filled up or down chevron when active.

Built as shared generic infrastructure rather than five bespoke implementations: a `compareValues(a, b)` comparator (nulls always sort last; strings compare case-insensitively via `localeCompare`; everything else compares numerically/by truthiness), an `applySort(rows, sort, columns)` function that looks up a column's value-getter and sorts (no-op when nothing is sorted yet, so each table's existing default order from `summarize()` is preserved until the user clicks a header), a `useSort()` hook per table holding `{key, dir}` state, and a `SortTh` header-cell component wrapping each label in a clickable button with the chevron indicator. Each table defines its own column-getter object (`FIELD_SORT_COLUMNS`, `ORGANIZER_SORT_COLUMNS`, `ADDRESS_SORT_COLUMNS`, `PLAYER_SORT_COLUMNS`, `BOOKING_SORT_COLUMNS`) mapping a sort key to a function that pulls the comparable value off a row.

Status-like columns use small numeric ranks so the "notable" state sorts to the top on the first click, matching how Michael described the Fields > Claim example: Claim ranks claimed (2) above pending (1) above unclaimed (0); Payouts ranks enabled above not-set-up; Field status ranks active above inactive; Email ranks sent above not-tracked above not-sent; Check-in ranks checked-in above not. Date-like columns (Joined, Booked) sort by underlying millisecond timestamp, not display string, so they order correctly regardless of format. Dollar columns sort by the underlying cents value.

Deliberately excluded: the Check-in Methods table (`CheckInMethodsSection`) — it has a pinned totals row and its own filter dropdown, a different structure from the other five plain listings, so sorting it wasn't in scope here. The Organizer detail modal's per-event table was also left as-is (it's a small, already-day-ordered sub-table inside a modal, not one of the five main dashboard listings).
